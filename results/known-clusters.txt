# Accounted-for cluster camps — the baseline `oracle/cluster.py --baseline` diffs against.

# roster: c,go,rust-std,rust-nostd,cpp,cpp-fixed,cpp-c-cpp,cpp-c-cpp-dyn,py-cython,py-pure,java,typescript,csharp,zig,dart,kotlin-jvm,kotlin-native
#
# ^ The drivers these signatures were recorded against. INFORMATIONAL: cluster.py matches
# each row on the drivers that row actually names, so adding a driver does not invalidate
# anything and this file does not have to be re-recorded for it. The stamp is printed as
# context when it differs, because "these signatures predate two of your drivers" is worth
# knowing while reading a result.
#
# What still turns a camp NEW, by design:
#   * a driver the row DOES name lands on the other side of the split — real movement;
#   * a driver the row does NOT name sits alone in a camp, agreeing with nobody. That is
#     the divergence most worth seeing on the day a driver is added, and an earlier version
#     of the matching swallowed it — see oracle/cluster.py:camp_matches.
#
# A camp belongs here ONLY once it is explained: a catalogued finding, a legal
# divergence, or a benign soft axis. Anything else is reported as NEW and the run
# exits non-zero. That is deliberate — the nightly has clustered and uploaded its
# result since it was written, nobody read the artifact, and nine unexplained camps
# accumulated unnoticed until 2026-08-03. An unread artifact is not a signal.
#
# The signature is the (driver-set, verdict) partition ONLY — not the representative
# and not the accepted bytes — so it survives the corpus changing under it.
#
# IT DOES NOT SURVIVE THE ROSTER CHANGING. Every signature names every driver, so
# adding cpp-fixed and cpp-c-cpp-dyn (crucible#129) invalidated all ten entries at
# once and the 2026-08-05 nightly reported "9 NEW CAMPS" — six of which were these
# same rows with the two new names inside them. A mechanism that cries wolf on a
# roster change trains people to stop reading it, which is the exact failure it was
# built to prevent. Rebased then; making it survive a roster change is in docs/TODO.md.
#
# A FIXED CAMP IS DELETED, NOT KEPT. A row whose cause has been repaired would match
# that camp again if it ever came back, reporting a regression as "known" — which is
# how F-0054's row was handled when it closed, and why its return was caught twice.
# So this file shrinks when the family improves.
#
# Rebased 2026-08-06 against sofabgen 0.0.0-20260806101130-dec1e42049cd and every
# corelib at its main tip, over the 9502-input corpus: 3884 agree, 5618 diverge ->
# **4 camps, all explained**. Nine rows were deleted in that pass, listed at the
# bottom for the record.
#
